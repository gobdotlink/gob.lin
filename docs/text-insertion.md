# Original-field text insertion

Settings → General → **Typing it in** offers **Insert dictation into**: **Current text field** uses the field focused when the transcript is ready; **Where I started** keeps the original field and remains the default. The choice is saved and captured when each recording starts, so changing it during processing affects subsequent recordings. Delivery notices and History name the selected destination app. Paste Last Dictation always uses the field currently chosen by the user.

In **Where I started** mode, each recording captures its original application, text control, window/document context, and selection before showing the overlay. Automatic delivery never activates an app or raises a window. If that control is still focused, the normal insertion pipeline runs against it. Otherwise, an editable control with readable text/selection and a writable `AXSelectedText` can receive a direct background write. The original window must still exist and its document must match. Editors that route changes through their app's selection must still identify the captured control as that app's focused element. Selection is restored only while the field's text is unchanged; edits made during recording use its fresh selection.

An unchanged empty original field can instead receive a direct `AXValue` write when supported. This handles editors that ignore selected-text writes in the background. Both captured and current selections must be at the start, and the captured value must still be empty (or a single empty-paragraph newline). The inserted text is verified literally, then caret placement at its UTF-16 end is acknowledged separately. An unconfirmed caret is reported without retrying the delivered text. Existing drafts are never replaced wholesale through this path.

Background writes leave the clipboard untouched and require exact text readback before showing **Text landed in [app]**. Unsupported, missing, or changed targets show **Ready to paste** and keep the transcript in History and Paste Last Dictation. They never redirect into the currently focused field. An accepted but unconfirmed write is reported separately and never retried automatically. App-only captures retain foreground paste compatibility but cannot be restored in the background. Manual Paste Last Dictation deliberately targets the field the user currently chooses.

`TextInsertionService.insert(_:)` is the native pipeline entry. Accessibility writes `AXSelectedText` first when the focused control exposes it as settable. A timeout or ambiguous write failure never triggers a second insertion. Unsupported writes fall back to paste. Accessible secure text fields reject insertion, and so does the app macOS names as holding Secure Input (or any app, when it names none). Another app guarding a password field doesn't block insertion elsewhere: macOS turns Secure Input on for the whole session, so a password box left focused in a background browser window would otherwise stop dictation everywhere.

Paste resolves the V key with `UCKeyTranslate` using the active layout's Command map (including Dvorak-QWERTY Command layouts). All synthetic events post on the main actor; Command is held for 15 ms before V (100 ms for remote desktop clients, which forward keys over the network) and always released, including cancellation. This hold is keyboard-event sequencing, never a clipboard-restore delay. Synthetic events are tagged so gob.lin's own modifier hotkey cannot react to its Cmd+V.

The entire previous clipboard is copied, preserving multiple items and data representations. If item retrieval fails, a promised representation cannot be read, or the clipboard changes during snapshotting, insertion stops before overwriting it. A genuinely empty item array remains a valid empty snapshot. The transcript uses a lazy `NSPasteboardItemDataProvider` with transient/concealed markers. Providers stay alive while the transcript remains available.

**A provider callback does not identify the consumer.** Clipboard managers can read first. Automatic restoration therefore requires all of: the provider was read, the original target remains focused, that target's accessible value exactly matches the expected replacement at its original UTF-16 selection (or, where an editor reports its caret in a different text space from its value, as T3 Code does beside a quote chip, differs from its previous value only by the transcript replacing one stretch), the value actually changed, and the pasteboard change count is still owned by this transaction. When the page itself has focus (an `AXWebArea`, as after selecting text in a T3 Code reply), the app may move the paste into one of its fields; restoration then requires the provider read, a newly focused field in the same app holding the transcript exactly once, and the owned change count. No arbitrary reader or elapsed delay can restore it. A three-second maximum only abandons verification. If confirmation is unavailable, gob.lin leaves the transcript on the clipboard and retains the original contents in memory for the explicit **Restore previous clipboard** menu/settings action. Recover those contents before quitting; recovery is not persisted to disk.

New pastes while the unverified transcript still owns the clipboard carry forward the original recovery snapshot. Failed transcript writes and failed restores also record the change count of their own empty/partial clipboard, preserving the original recovery across an unchanged retry. An intervening external change breaks that count match, so the newer contents are snapshotted instead. A newer clipboard change is never automatically overwritten. The menu and global ⌘⌥⇧V shortcut paste the last completed transcript; the engine pipeline must supply that transcript. The trailing-space preference defaults on and does not duplicate existing whitespace.

| App family | Strategy and limitation |
| --- | --- |
| Notes and standard Cocoa editors | Accessibility insertion where supported; otherwise verified paste |
| Terminal / Ghostty | Paste only, avoiding repeated direct typing; terminal AX content often cannot confirm consumption |
| Paseo / VS Code / Cursor / Slack / ChatGPT (Codex) | Paste handles Electron editing; exact AX evidence is used only when exposed. Electron is recognised by its framework, its `app.asar` archive or the `ElectronAsarIntegrity` Info.plist key, so apps that rename the framework (the ChatGPT app ships it as Codex Framework) paste too |
| T3 Code | Paste while focused, with exact empty-paragraph normalization; unchanged empty original editors also support verified background value insertion; a paste made while the conversation has focus is confirmed in the message box T3 moves it to |
| Dia / Chrome / Arc | Paste preserves browser input handling; address bars may normalize trailing whitespace and therefore require explicit recovery |
| Remote desktop / VNC / AnyDesk / TeamViewer | Paste only; local AX cannot confirm remote consumption, so automatic recovery is disabled |
| No focused AX control | Paste into the same foreground app; no automatic recovery without target text evidence |

Run `bash scripts/check-insertion.sh` for safety assertions: UTF-16 selection replacement, trailing spaces, no restoration on a clipboard-manager read, focus changes or clipboard ownership changes. `bash scripts/check-native-insertion.sh` exercises a real isolated named pasteboard with lazy data, multiple items, HTML and binary data; it checks the active layout without touching the general clipboard. End-to-end target-app acceptance across every named app and Dvorak/AZERTY still needs an interactive session with those apps/layouts. No actual recognizer is wired before the benchmark.

## Watching edits after paste

When **Watch edits after paste** is enabled (Settings → General, on by default) and an insertion was verified against the target's accessible value, gob.lin keeps the target element and the expected value split around the inserted span. For up to 30 seconds it re-reads that one element's value twice a second and measures grapheme-level edit distance between the inserted text and the span as it now stands. The watch is read-only: it never writes accessibility attributes or touches the clipboard, and it ends early on focus loss, Secure Input in the watched app, the field becoming secure or unreadable, the next dictation, or keys that mean the user moved on (Return, Tab, Escape, another paste). Undo remains observable: deleting the pasted span by undo is recorded as rejected on the next sample. Secure fields are excluded by the same checks as insertion, credential-manager apps are never watched, and fields over 20,000 characters are skipped.

History records an outcome per dictation: **kept** (no change), **edited** (final distance within half the inserted length, with a 10-grapheme floor for short dictations — the final span text is stored and shown as a diff), **rewritten** (beyond that threshold — distances only, the field's text is never stored, since it may be unrelated typing), **rejected** (the span was deleted), or **unobservable** (no fresh, trustworthy sample; silence never counts as kept). The pure measurement and classification live in `EditObservation` (GoblinCore) with unit tests in `EditObservationTests`. End-to-end behaviour across target apps still needs interactive per-app trials; automated checks cover the classification, not live accessibility reads.

A signed live trial on this Mac verified pasting into T3 Code's empty composer, correcting a name, ending the watch with Tab, persisting the edited span, and displaying its diff in the production History view with isolated data. That trial exercised insertion and observation directly; it did not run microphone capture or speech recognition.
`bash scripts/build-original-field-check.sh <private-output-directory>` builds certificate-signed native fixtures for original-field delivery. Under the shared desktop lock, launch `Original Field Target.app`, then the fixture `gob.lin.app`; inspect `result.json` and `delivery-notice.png`. The check exercises a real background write into the captured selection while another field/app stays untouched, manual recovery for unsupported/missing targets, document/window invalidation, ambiguous-write suppression, foreground paste recovery, and queued destination notices. It uses isolated editor drafts and preserves the general clipboard through the normal verified-paste transaction.
