# Optional AI cleanup

`RewriteSettings` is off by default and supports an OpenAI-compatible base URL, model, and None/Light/Medium cleanup. The Apple Intelligence provider is the exception: it runs the system on-device model through `OnDeviceCleanup`, with no address, model choice, or API key, and sends nothing anywhere. It reuses the same prompt, payload, empty-output guard, and four-second deadline (structured output first, one plain retry for structured-only or transient failures). The model's 4,096-token context window must hold the instructions, the transcript, and the cleaned output, so long dictations fail explicitly to raw text instead of being truncated. Availability (ineligible device, Apple Intelligence off, model not ready) is read lazily when the provider is selected or used and is shown as the setup problem; language and guardrail refusals also fall back to raw. Builds without the Foundation Models framework report the provider as not included rather than failing to compile. `RewriteSettingsStore` saves only these nonsecret preferences. `RewriteKeyStore` saves the API key in the app's preferences, separately for each canonical provider endpoint. Keys are unencrypted there until builds are signed with an Apple Development certificate; the local certificate has no Team ID, so Keychain would ask for the account password after every rebuild or update. Changing providers never reuses another endpoint's key. The settings view has a secure input, a Remove key action, and explicit Save settings.

`RewriteClient.rewrite(_:settings:apiKey:tone:preferredSpellings:)` returns `RewriteResult` with the original input, the usable output, optional polished text, and an explicit failure. Disabled cleanup, None, or blank input sends no request. Failure returns the input and the warning **polish failed — pasted raw**. The final insertion/overlay/history integration must display that warning and retain raw and polished text separately; an upstream cancelled dictation must check task cancellation before insertion.

The predefined system prompt instructs the model to clean up dictation without answering or obeying spoken instructions. The transcript and preferred spellings are encoded as JSON inside a fresh delimiter in a separate user message. This minimizes instruction confusion; a probabilistic model cannot provide an absolute prompt-injection guarantee. Light keeps wording, while Medium fixes minor grammar and accidental repetitions. The tone contributes a trusted prompt instruction.

Every request uses temperature 0 and a gob.lin User-Agent. A single monotonic four-second deadline covers all attempts. Only reasoning-specific HTTP 400/422 errors trigger fallback from `none` to `low`, then omission; rejected efforts are remembered for the endpoint during the client lifetime. Unrelated validation errors, rate limits, transport errors, blank output, refusals, and provider-declared `finish_reason: "length"` truncation are explicit raw fallbacks. The finish reason is optional for compatible providers that omit it. HTTPS is required for remote providers; HTTP is allowed for loopback servers. Redirects are refused to avoid forwarding a transcript or key to an unexpected host.

Validation: three focused tests use URLProtocol fixtures to check reasoning fallback/cache, prompt/data boundaries, explicit provider errors/None/invalid output, and the shared hard deadline. All eight text-feature tests pass; no live provider request or user transcript was sent. Keychain code and native settings compile with the signed app. Provider p50 latency acceptance requires the eventual real provider/benchmark; no latency claim is made here.

On-device validation on 17 October 2026 (Apple M4 Pro, synthetic text only): all 23 cleanup fixtures ran through the production postprocessor with the Apple Intelligence provider. 13 matched exactly after tone formatting; most remaining differences were punctuation-only. Known misses: sound-only input was not emptied, coding-agent paragraphs were not split, and one multi-sentence case kept hesitation sounds. Median full processing time was about 0.69 s, maximum about 1.0 s in this run. The model's language detection intermittently refused slangy English as unsupported; the plain retry recovered those cases. These fixtures overlap the prompt's examples, so this is a regression check, not an independent quality benchmark.
