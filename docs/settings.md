# Settings

One native settings window exposes General, Audio, Model, Dictionary, Post-processing, Tone, History, Overlay and About. Existing feature views share the same services as the menu bar and history. Changes persist under stable preference keys and apply without a restart; shortening retention requires Apply to prevent deletion while editing.

Every page except History is a set of sections inside one shared grouped Form, under one shared header (title plus a one-line `//` comment), so margins, grouping and scrolling match across pages. History keeps its list/detail split with the same header and 20pt margins. The window is capped at 960pt wide: grouped Forms center a narrower column in wider windows, which would break that alignment.

Microphones are stored by Core Audio UID, with a follow-system option. The explicit local level preview requires an existing microphone grant, becomes ready only after its first buffer, and stops when leaving the page or permission is revoked. A missing saved device falls back without erasing the preference. Preview callbacks are session guarded. This is a level preview, not the GOB-8 capture engine.

The meter displays the loudest channel's RMS as device input, so a microphone on a later interface channel is visible. This does not select or downmix a recognizer input. An audio-engine format/configuration change stops the current preview and explains that it must be started again; callbacks from an older preview cannot change the new session.

Login Items uses SMAppService and reports approval/errors. Audio capture, sounds, model download and recognizer binding remain separate benchmark/capture work; model selection clearly shows this pending state. Dictionary, rewrite credentials, tone, insertion space and clipboard recovery are real controls; no live provider request is made by opening settings.

Login Items status refreshes when General appears, when gob.lin becomes active, and after each attempted change. History's count picker distinguishes no limit from zero unstarred entries, preserves custom saved counts, and reloads a newly saved policy from the History window.

Checked: SwiftPM build, signed app verification, Xcode debug compilation. Permission changes and login-item registration are user actions and are not toggled during automated verification.

Post-processing includes provider presets ordered with Cerebras and Groq first, followed by OpenAI, OpenRouter, Z.AI, Local and Custom. A fresh installation starts with Cerebras / Qwen 3.8 27B and reasoning Off, with AI cleanup still disabled. Existing settings preserve the URL, model, cleanup level and Automatic reasoning fallback. Switching providers remembers their non-secret configuration on Save; credentials remain scoped to the actual endpoint in Keychain. Custom starts from the current configuration, and every URL and model remains editable.

Model shortcuts set the model, reasoning, temperature and model-specific options together. Groq defaults to inexpensive GPT-OSS 20B with Low reasoning and hidden reasoning output; its Qwen shortcut requests Off. OpenAI offers GPT-6 Luna; OpenRouter offers Luna and Claude Haiku 5.5. Haiku omits temperature because its API rejects sampling parameters. Explicit Off/Low/Medium/High choices are never relaxed after a provider rejection. Automatic retains the none → low → omitted fallback for conventional `reasoning_effort` endpoints, scoped by both endpoint and model; OpenRouter and Z.AI use their native reasoning/thinking fields.

Groq GPT-OSS requests use `include_reasoning: false`, removing the unsupported `reasoning_format` option; Groq Qwen uses `reasoning_format: hidden`, without the mutually exclusive `include_reasoning`. These final-text controls remain managed after an effort change, an advanced-options override, or loading an older profile, so cleanup cannot paste the model's reasoning. See [Groq's model-specific reasoning controls](https://console.groq.com/docs/reasoning). For OpenAI/OpenRouter Luna, temperature, top_p, top_logprobs and logprobs are omitted unless the effective request explicitly disables reasoning, including Automatic fallback attempts; the saved values remain available when returning to Off. See [OpenAI parameter compatibility](https://developers.openai.com/api/docs/guides/latest-model#update-api-and-model-parameters).

Advanced options allow omitting or adjusting temperature and adding a JSON request object. Top-level null removes a default field. Custom reasoning options require Provider default; model, messages and stream cannot be overridden. Options are validated before saving a credential or issuing a request. Prompt isolation, app User-Agent, the shared four-second deadline and visible raw-text fallback still apply. No provider request is sent by opening settings or selecting a preset.

The AI cleanup section shows the saved on/off status separately from edits, marks unsaved changes, and keeps Save settings next to the enable switch. Entering or saving a key does not implicitly enable cleanup. Test cleanup is available after saving an enabled configuration; it sends only the synthetic sentence “i will send the report tomorrow morning” and reports provider success, full-response time, or a visible error without creating a dictation or changing the clipboard.

Cleanup presets use an original prompt informed by published dictation prompts and behavior, including [Superwhisper S1-mini](https://huggingface.co/superwhisper/s1-mini), [VoiceInk](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Core/Enhancement/AIPrompts.swift), and [OpenWhispr](https://github.com/OpenWhispr/openwhispr/blob/main/src/locales/en/prompts.json). These are public sources, not verified leaks of closed products. The prompt combines explicit editing boundaries with short paired examples; transcript and vocabulary remain isolated as untrusted JSON data.

| Cleanup | Behavior |
| --- | --- |
| None | Skip the provider |
| Light | Remove hesitation sounds and accidental immediate stutters/restarts; fix punctuation and clear transcription errors; retain wording and paragraph structure |
| Medium | Light plus minor grammar and clear self-corrections, keeping the final explicitly corrected phrase/value |
| Coding agent | Light plus paragraphs for new points, clear spoken command syntax and issue IDs/numeric values; no headings, bullets or invented commands |

All active presets preserve slang, swearing, intentional repetition, conversational words, language and correctly heard names. Vocabulary only clarifies clear mishearings; it cannot expand “Luna” to “GPT-6 Luna”. Meaningful words such as German “um”, quoted hesitation words, and uncertain phrases stay intact. Questions and instruction-like speech are punctuated rather than answered. Tone remains a separate capitalization/punctuation setting; Formal does not formalize the speaker's vocabulary.

A normally completed response may legitimately contain no text for sound-only input. Empty output is accepted only for a conservative hesitation-token sequence containing an explicit sound such as “uh” or “erm”, with no protected vocabulary term, and an explicit `stop` finish reason. Cerebras may omit the content field for this response. Substantive input, ambiguous lone “um”/“er”, refusals, truncation and incomplete responses retain the visible raw fallback. This does not apply a blanket filler-removal regex to multilingual dictation. Successful intentionally empty cleanup skips insertion without a missing-transcript warning, leaves the previous pasteable transcript intact, and keeps the original text/audio in History. Missing ASR output and provider failures still warn. An isolated app completion check exercises this path without microphone grants, provider calls or clipboard changes.

Prompt verification on 14 October 2026: 18/18 short synthetic cases passed through the production `TranscriptPostprocessor` with saved Cerebras / Qwen 3.8 27B settings, reasoning Off and temperature 0. They covered hesitations, stutters, intentional repetition, slang/swearing, meaningful conversational words, instruction-like speech, contextual vocabulary, name preservation, German “um”, filler-only empty output, cleanup-level differences, and coding commands/issue IDs/paragraphs. Median full processing time was 0.258 s, maximum 0.353 s in this small run. Some fixtures overlap prompt examples, so this is a regression check, not an independent quality benchmark. The [synthetic fixture set](../Tests/RewriteCleanupFixtures/cases.json) also includes five additional tone/longer-sentence cases; their live run was blocked by Keychain access in the temporary helper, and they are not counted as passing. `swift test` passed 21 offline safety/settings tests, including destructive-empty-output guards; smoke checks passed.

Live verification on 14 October 2026: the signed app's Test cleanup succeeded with saved Cerebras / Qwen 3.8 27B settings and reasoning Off in 0.24 s, returning “I will send the report tomorrow morning.” [Settings evidence](screenshots/postprocessing/test-cleanup.png). This is one synthetic request, not a p50 dictation benchmark. An earlier Keychain error disappeared after cleanly relaunching the final signed build.
