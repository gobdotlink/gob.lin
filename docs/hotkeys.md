# Native hotkeys

The dedicated event-tap thread owns its run loop, tap, and source. Revocation sets the stop flag, stops and wakes the run loop, then removes its source and invalidates the port. A timeout re-enables the tap in its callback. There is no enabled-state polling. Permission checks use the separate onboarding monitor. The modifying session tap requires Accessibility; Input Monitoring is informational and does not gate Fn, modifier-only or keyed shortcuts, including the Carbon fallback. Actual tap creation still determines availability.

Any key or combination macOS delivers can be the talk key: a plain key (Insert, Esc, a letter), a key with modifiers including Fn, or one or more modifier keys alone. A modifier-only shortcut keeps the exact keys pressed, so Right Control and Left Control stay distinct, using the device-dependent side flags. It presses when its last key goes down and releases when any of its keys comes up. Keyed shortcuts match their modifiers on either side. macOS adds the Fn flag to F-keys, arrows, Insert, Home, End and Page keys itself, so Fn is ignored on those. Set Keyboard → Press Globe key to → Do Nothing to use Fn. Some keyboards keep keys or Fn to their firmware, or send a macro (Win+C arrives as Command+C); the recorder shows what actually arrives. Modifier events pass through so ordinary chords still work. A non-modifier key or extra modifier invalidates a modifier-only tap; a chord after the hold threshold cancels the recording state.

A 300 ms threshold distinguishes hold from tap. Key repeats are ignored; a 15 ms release hold-back absorbs repeat pairs, which remappers and macro keys send within a few milliseconds. A raw release marks the hold as pending release immediately, so a queued threshold callback cannot convert a short tap into a hold during that interval. Escape is consumed only during a recording state, and not at all when Esc is the talk key; the overlay's × cancels instead. Capture starts immediately even if an earlier transcription is processing; completed captures queue for processing. The service exposes `onAction` and `processingCompleted()` for the engine pipeline. With no engine callback, it exercises shortcut state only and never claims audio is being recorded.

Secure Input is checked on the main thread every 500 ms and at Carbon press delivery. A keyed shortcut is registered with Carbon for both `kEventHotKeyPressed` and `kEventHotKeyReleased`. The paired release remains accepted if Secure Input turns off during a hold. Modifier-only and Fn shortcuts pause and show a visible warning; they cannot bypass Secure Input. Escape's Carbon registration exists only during recording. Sleep and session resignation stop capture cleanly; wake and session activation restart the tap. Callback disable notifications clear pending/recording state safely.

Shortcut preferences persist in UserDefaults. The native recorder suspends global capture while collecting local events, shows the combination as it arrives, saves a key on its release and modifiers alone 250 ms after they are all up, so a macro that taps a modifier first records whole. It refuses nothing; it notes when a choice stops a key typing, takes over a Command shortcut, replaces Esc, or pauses under Secure Input. Cancelling keeps the previous key. Fn, Right Option and Option+Space stay as presets.

Run `bash scripts/check-hotkeys.sh` for the narrowly scoped state safety checks (tap/hold/chord/Escape/processing overlap/repeats) and shortcut capture and matching, replayed from recorded external-keyboard traces and every modifier combination. Native hardware acceptance requires user-approved grants and keyboard interactions. Engine wiring and actual audio acceptance remain dependent on the benchmark.
