# Diagnostics and visible failures

`DiagnosticFailure` maps typed failures to static, user-visible messages. It covers microphone access/device/capture, permissions, hotkeys, Secure Input, model/load/ASR, silence trimming, rewrite configuration/timeout/transport/HTTP/invalid output, insertion permission/target/clipboard/acknowledgement/general failure, History, Dictionary, settings, and a safe generic operation failure. `DiagnosticFailure.rewrite(_:)` deliberately drops arbitrary configuration error strings. Provider status codes are the only provider error detail included.

The shared `DiagnosticsModel` exposes `hasWarning`, `warningMessage`, `warnings`, `report(_:)`, `resolve(_:)`, `refresh(permissions:secureInput:engineStatus:)`, `recordTimings(_:)`, and `copyDiagnostics(includeDeviceNames:)`. Root AppModel/pipeline integration must use the same instance for the pill, warning mascot/menu, diagnostics view, and service callbacks. Report each typed failure before returning from its failure path, and resolve its area after successful recovery. Clearing recent events does not clear active warnings. The model deduplicates ongoing identical warnings and bounds recent events to 50 in memory.

`refresh` only reads existing permission status, Secure Input, and available microphone names; it never requests or grants permission. Missing permissions/device and Secure Input become active warnings. Other runtime errors arrive through `report` from the service or pipeline. Subsystems use `app.goblin.dictation.<area>`; performance uses `app.goblin.dictation.performance`. Every logged message is derived from typed/static data, never a raw error description.

Copied diagnostics contain app/OS/architecture versions, permission statuses, Secure Input, engine readiness, microphone count, active/recent typed errors, and the latest capture → silence trimming → ASR → rewrite → insertion timings. Names are omitted unless the user enables the sharing toggle. Transcripts, API keys, provider request/response bodies, target apps, audio names, and user file paths are never accepted by the report API. Device names are intentionally available by explicit opt-in and can identify hardware.

`recordTimings` logs the same `DictationTimings` value that the final pipeline must store in `HistoryEntry.latencies`. No recognizer timing is fabricated while engine selection is pending. Non-finite or negative timing values display as unavailable.

Validation: `swift run DiagnosticsSmoke` checks raw configuration string removal, device-name default omission, typed failure visibility, the 50-event report bound, permissions, and non-finite timing safety. Native view builds in SwiftPM and the generated Xcode project. Final menu/pill/service wiring is owned by the settings/pipeline integration, not a second diagnostics instance in this branch.
